## 一、做什么

用户已有连陪/单班主单在履约中（或整包未结束），希望在**同一服务规格**上向后延长天数，而不重新走确认页选商品、地址、被护理人。

- **续单 ≠ 加开另一班**：不能在「只有日间」的原单上通过续单补出夜间（反之亦然）。日+夜只能续已有主单对应的班次。
- **轻量路径**：列表/详情点「续单」→ 底部抽屉选续约天数（日+夜时可勾选要续的主单）→ 协议 → 支付方式叠层 → 支付成功。

---



## 二、单据模型（方案 A）


| 项               | 规则                                                   |
| --------------- | ---------------------------------------------------- |
| 主单              | **不新开商品主单**。对勾选到的每一个已有主单，在原主单上**拉长服务天数 / 追加预约**      |
| 支付              | 产生**续费支付单**（或等价支付流水），金额 = 本次勾选主单 × 续约天数对应费用；与首单支付单分离 |
| 预约              | 按各自主单班次，从衔接日起连续追加 N 个预约                              |
| 人员              | 文案承诺：**优先安排原服务人员**；原人无档时安排其他人员（不在续单抽屉内改人）            |
| 地址 / 被护理人 / SKU | 沿用原主单，续单流程不改                                         |


一侧预约已全部完成、主单状态已是「已完成」，但整包仍在可续窗口内且用户勾选该侧：允许对该主单**再拉长并生成后续预约**（状态需支持从已完成回到可履约/服务中，由履约侧落地）。

## 三、入口与列表呈现



### 3.1 入口


| 位置         | 按钮文案 | 行为                           |
| ---------- | ---- | ---------------------------- |
| 订单列表 · 主单卡 | 续单   | 打开续单抽屉；`entry` = 该卡对应班次（日/夜） |
| 订单详情底栏     | 续单   | 同上；`entry` = 当前详情主单班次        |


不可续时：**不展示**续单按钮（不做置灰可点）。

### 3.2 列表结构（日+夜）

原下单为日+夜时，列表按**两张主单卡**展示（日一张、夜一张），各自有「续单」。  
仅日 / 仅夜原单：一张主单卡。

列表副文案（hint）示例：`待服务 | 服务人员将在上门前2小时内联系您`（**不**在 hint 中重复写服务区间与「每日 xx:00 上门」）。

---



## 四、可续窗口



### 4.1 仅日 / 仅夜原单

该主单时间上**最后一班服务尚未结束** → 可续。  
最后一班结束后 → 入口消失。

（与首单「服务结束前 1 小时不可再约该班」是下单截止；续单窗口以**整段履约是否结束**为准，不以结束前 1 小时截断入口。若业务后续要对齐截止线，另开变更。）

### 4.2 日+夜组合原单（关键）

以**当前履约视图**下、组合内时间上**最晚仍未结束**的那一班为准（不论日或夜；含历次续单拉长后的预约）：

- **该班未结束前**：日、夜两张卡均可展示「续单」；抽屉内**两侧主单均可勾选**（含一侧预约已全部完成、另一侧仍在履约的情况）。
- **该班已结束**：整包不可再续，两侧入口均消失。

> 可续窗口按**整包当前最晚未结束班**判断，不是首单原始结束日；**起算与计费仍按各自主单**（见第五章）。



### 4.3 与「再来一单 / 新购」边界

过可续窗口后，用户走普通下单或「再来一单」，不走续单。

## 五、衔接起算与天数



### 5.1 起算（核心规则）

**锚点**：对该主单，取**已存在预约中结束时刻最晚的那一班**（含待服务 / 服务中 / 已完成等未取消预约；多次续单后以当前主单上最晚一班为准）。

**续段**：从该锚点的**下一班**起，按该主单班次连续排 N 天（N = 该侧续约天数）。


| 勾选主单 | 续段开始               |
| ---- | ------------------ |
| 日间主单 | 日间主单锚点日班的**下一场**日班 |
| 夜间主单 | 夜间主单锚点夜班的**下一场**夜班 |


日、夜同时勾选时：各自按上表衔接，**不强行共用同一个开始日**；**续约天数各自独立**（可为日 2 天、夜 3 天）。

### 5.2 服务中 / 进行中时怎么接

- 若锚点班正在上门（服务中 / 进行中）：**仍以该班为锚点**，续段从其下一班起排。
- **不**因「今天正在服务」改为从今天重排，**不**与正在进行的班重叠，**不**在锚点与续段首班之间人为空一天。
- 续单只**追加**预约，不改写、不拆分锚点班及更早的已有预约。

**示例**：日间主单已有 11/2、11/3、11/4；当前为 11/4 10:00 且 11/4 日班服务中；续 2 天 → 追加 **11/5、11/6** 日班（不是从 11/4 再算，也不会空出 11/5）。

### 5.3 天数

- 每个已勾主单各自有一个续约天数，打开时默认均为 **1** 天；可分别 ±。
- 最少 1 天；上限与连陪首单一致（原型 30，线上跟配置）。
- 只排连续自然日对应班次；续单自身不制造跳日（原单若已有空洞，锚点仍取「结束时刻最晚」的那一班，续段从其下一班连续排）。
- 仅日 / 仅夜原单：抽屉内一个天数选择器即可。



### 5.4 抽屉内排期摘要

每个已勾主单在其服务块下方展示：续约天数选择器 +「开始 / 结束」摘要（由该侧锚点下一班 + 该侧天数 + 班次算出）。

## 六、续单抽屉交互



### 6.1 结构（自上而下）

1. 标题：**续单**（统一文案，不区分入口）
2. 人员说明：优先原服务人员；原人无档安排其他人
3. **主单勾选区**（仅日+夜原单出现）：每个服务下方挂该侧的续约天数 ± 与排期摘要（勾选后显示）
4. 仅日 / 仅夜：无勾选区，一个续约天数 ± + 排期摘要
5. 平台服务协议（**默认不勾选**）
6. 合计 + 查看明细 + 立即支付



### 6.2 日+夜勾选规则


| 规则      | 说明                                         |
| ------- | ------------------------------------------ |
| 默认      | 只勾选**当前入口对应**的那一侧（从日卡进 → 默认勾日；从夜卡进 → 默认勾夜） |
| 可改      | 用户可加勾 / 取消另一侧；至少保留一侧                       |
| 天数      | **两侧天数彼此独立**；勾上哪一侧，就在该服务下方出现该侧天数选择器        |
| 仅日或仅夜原单 | **不展示**勾选区，隐含只续当前这一单；一个天数选择器               |
| 不可      | 通过续单勾出原单没有的班次                              |




### 6.3 协议与支付

- 协议默认**未勾选**；未勾点「立即支付」→ Toast「请先勾选平台服务协议」。
- 点「立即支付」后：**在续单抽屉之上叠支付方式层**，**不关闭**续单抽屉。
- 关闭支付层 / 点遮罩：回到续单抽屉（内容保留）。
- 支付成功：关闭支付层与续单抽屉；Toast 示意续费结果；主单天数 / 预约列表应刷新为拉长后状态。



### 6.4 费用明细

- 「查看明细」打开明细层（服务费、等级加价、耗材、上门费、合计等，口径对齐该 SKU 与天数）。
- 明细层在续单抽屉之上；关掉明细仍留在续单抽屉。
- 拉起支付前若明细层开着，先关明细，再叠支付（续单抽屉仍在）。



### 6.5 合计

合计 = Σ（已勾主单的续费单价 × 该侧续约天数）。  
单价含该主单对应服务费、上门费等现行计价项（与确认页同 SKU 规则一致；续单不重新选等级/耗材时按主单已生效规格计）。

## 七、与购物车 / 其他通道


| 项       | 要求                      |
| ------- | ----------------------- |
| 续单通道    | 独立于购物车；**禁止**与购物车商品合并结算 |
| 连陪确认页首单 | 与续单互不串单；续单不进入确认页推荐搭配流程  |
| 加购另一班   | 不属于续单；走新购 / 确认页推荐       |


本期若不做技术隔离，至少：续单支付单不得附带购物车行；前端续单路径不提供进购物车。

---



## 八、状态与异常


| 场景 | 处理 |
| --- | --- |
| 锚点班正在服务中 | 仍从该班下一班起排续段；见 §5.2 |
| 可续窗口内，一侧主单预约已全部完成 | 整包未结束则仍可展示入口；抽屉内该侧仍可勾；支付后按该侧锚点下一班拉长 |
| 支付时整包最晚未结束班已结束 | **不扣款**；关闭续单抽屉与支付层；提示不可续（交互另定） |
| 原人无档 | 不阻断支付；履约按「安排其他人员」 |
| 用户取消支付 | 不改主单；抽屉可继续改天数后再付 |
| 网络 / 支付失败 | 不拉长主单；可重试 |

## 十、不在本期

- 续单抽屉内改地址、被护理人、SKU、等级、耗材、指定其他人
- 续单补开原单没有的班次
- 续单与购物车合并支付
- 首页连陪问卷入口上的续单（续单只挂订单列表/详情）

## 十一、验收要点

1. 日+夜列表两卡，按钮均文案「续单」；hint 无「11/x–11/x · 每日 xx:00 上门」。
2. 日+夜：整包最后一班未结束前两侧可续、可勾；结束后两侧入口无。
3. 抽屉默认只勾入口侧；协议默认不勾。
4. 支付叠在续单抽屉上，取消支付抽屉仍在；成功后两者都关且主单展示已拉长。
5. 仅出续费支付单 + 原主单拉长，不新开同 SKU 主单；不进购物车合并。
6. 起算 = 各自主单「已有预约中结束最晚的一班」的下一班起连续排；服务中不改锚点、不重叠、不人为空日。
7. 日夜同时勾选时天数各自独立（选择器在各服务下方）；可续窗口随历次拉长后的最晚未结束班移动。
