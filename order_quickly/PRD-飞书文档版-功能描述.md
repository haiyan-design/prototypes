## 二、文档概述

| 项 | 内容 |
|----|------|
| 需求编号 | R-261022-019 |
| 需求名称 | 快速帮用户找到服务 |
| 业务目标 | 让有连续陪护需求的人群能够快速下单 |

### 需求背景

1. 目前对于需要一天 24 小时服务的用户，要下两单（日陪 12h + 夜陪 12h），并且预约两次，增加理解成本，不方便。
2. 对于需要连续（多天）24 小时服务的用户，除了分成日陪、夜陪的主单，还要预约多次子单，且上门服务人员不一定是同一个人。
3. 用户进到小程序寻找自己想要的服务难度大。

### 需求概述

1. 首页放置「连陪快约」入口（悬浮球）。
2. 用最少的问题，帮需要连续陪护（含日间 / 夜间 / 日间+夜间）的用户快速生成 **X 天**服务（**默认最少 3 天**，可自行加天数，最长 14 天可配置），并快速下单（为自己、为他人）；用户只需选择一次日期区间。
3. 针对 24 小时（日间+夜间）服务：用户需要全天或连续多天时，**日班全部日期同一人、夜班全部日期同一人（共 2 人）**；用户侧一笔支付、一次选齐日期即可。

## 三、整体方案

### 基础术语

| 术语 | 解释 | 示例 |
|------|------|------|
| 连陪快约 | 首页入口进入的连续陪护快速下单流程 | 首页悬浮球「连陪快约」 |
| 服务场景 | 服务发生地点类型 | 住院 / 居家 |
| 服务类型 | 班次组合 | 日间+夜间 / 仅日间 / 仅夜间 |
| 连续自然日 | 开始日至结束日之间不间断的日期区间 | 10/24–10/26，共 3 天 |
| 支付单 | 用户一笔支付对应的头订单 | 支付成功生成 1 张支付单 |
| 主单 | 按班次打包的履约单，整包抢单 | 日间主单、夜间主单 |
| 预约单 | 主单下按「自然日 × 班次」拆分的子单 | 日间主单 ×3 天 → 3 条预约 |
| 整包抢单 | 护工按主单接全部天数，不可按天拆抢 | 3 个日单只能被 1 人接完 |
| 上门时间 | 服务确认页上的日期选择入口（本需求改造为连选区间） | 请选择 → 展开日历 |

### 总体描述（架构 / 流程）

**两条下单路径：**

1. **方案一｜首页连陪快约**：悬浮球 → 一页问卷（场景→类型→日期）→ 确认信息页 → 支付半层。  
2. **从服务去下单连陪**：商详「立即预约 / 去下单」进入服务确认页 → 改造后的上门时间连选 → 立即支付。

**支付成功后单据（日间+夜间 × N 天）：**

```
用户一笔支付
  └─ 支付单 ×1
       ├─ 主单·日间（×N 天）→ 预约 ×N → 护工 A 整包
       └─ 主单·夜间（×N 天）→ 预约 ×N → 护工 B 整包
```

仅日间或仅夜间：支付单 ×1 → 主单 ×1 → 预约 ×N → 护工 1 人整包。

**业务规则摘要：**

- 仅支持连续自然日；**最少 3 天，最多 14 天**（可配置）。
- 用户不可改服务钟点；展示 SKU 默认时段。
- 连续陪护路径 **仅立即预约**（不提供先买后约）。
- 同班次多日同一人；日间+夜间为 2 人（日 1 人 + 夜 1 人）。

> 流程图见仓库 PRD §5.3（问卷端到端 + 单据抢单）。飞书中可嵌入原型录屏 / 截图。

### 技术要求（如有）

1. 支付成功与支付单 / 主单 / 预约创建需事务一致或可补偿，避免只扣款无单。
2. 抢单接口按 `master_order` 整包接单；禁止按单日预约抢单；同一主单下全部预约 `caregiver_id` 必须一致。
3. 下单需记录 `entry_source`：`连陪快约` / `服务确认页`。
4. 最少 / 最多连续天数、四类 SKU 默认时段支持配置下发。
5. 不影响现有单次 12h 商详、加购、先买后约主路径（服务确认页本需求仅改连续陪护相关交互）。

**本需求改造点：** 支持连续多天下单；去掉与连续陪护冲突的交互。

## 六、风险 / 问题

| 序号 | 风险 / 问题 | 说明 | 建议 |
|------|-------------|------|------|
| 1 | 上门费计收口径 | 按支付单收 1 次，还是日/夜主单各收 1 次？ | 评审前与运营确认；影响金额与退款 |
| 2 | 优惠券分摊 | 支付单级核销时，日/夜金额如何分摊与退款？ | 财务 / 交易评审 |
| 3 | 主单超时无人整包 | 连续多天整包接单难度高于单日，超时与自动退策略需明确 | 运营定超时时长与文案 |
| 4 | 从服务页仅单班次 | MVP 从单 SKU 进入只能下当前班次 × N 天，无法在同页组 24h | 接受或二期加类型切换 |
| 5 | 取消其中一天 | 若支持按天取消，将破坏「整包同人」与退款复杂度 | MVP 建议仅整笔退 |
| 6 | 入口曝光 | 悬浮球是否打扰、是否全量 | 建议城市 / 标签灰度 |
| 7 | 与旧抢单并存 | 上线前需确保连续陪护主单走整包逻辑，旧按次抢单不串单 | 履约域回归用例 |
