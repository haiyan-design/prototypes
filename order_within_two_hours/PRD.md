| 项 | 内容 |

---

## 1. 背景与目标

### 1.1 背景

院内上门时效更短，用户常有「尽快」诉求。若仍沿用偏长的最早可约逻辑，转化与体验都会受损。需要在院内支持约 30 分钟近约，同时保留按日期 / 半点预约，且**不**用单独卡片重推「尽快」。

### 1.2 目标

1. 尽快精确时刻**并进**当天时间滚轮，与半点同一套选择。
2. 规则清晰：尽快 = 现在 + 30′（精确到分）；其后为半点。
3. 比尽快更早只走客服，不开放更早自助时段。
4. 列表预约、订单页立即预约、先买后约三入口规则一致。

### 1.3 非目标

- 不改变院外预约时效与默认逻辑。
- 不开放「比尽快更早」的自助可选时段。
- 预约结果只存**一个开始时间**（非整段区间）。
- 不做「尽快 / 指定时间」二选一单选卡片。

---

## 2. 核心规则

### 2.1 尽快时刻

| 项 | 规则 |
| --- | --- |
| 计算 | `尽快时刻 = 当前时间 + 30 分钟`（保留到分钟，不凑半点） |
| 滚轮呈现 | 作为当天滚轮**第一项**；分钟旁极弱 **⚡**（选中略清晰）；**不**写「尽快」文字角标 |
| 确定回填 | 若选中尽快项：`尽快上门 · HH:mm`（例 `尽快上门 · 16:23`） |
| 打开默认 | 默认选中该最早项，但打开半屏落在**日期 Tab**；时间 Tab 浅色显示该时刻 |

### 2.2 可约时刻（滚轮）

| 场景 | 可选时刻 |
| --- | --- |
| **当天** | 尽快精确时刻 + 其后半点至 23:30（例 16:23 → 16:30 → 17:00…） |
| **其它日期** | 全天半点 00:00–23:30（无营业时段限制） |

- 换日期时尽量保留当前选中的时:分；不可用则落到该日最早可约项。
- 换小时时：落到该小时**最早可选项**（不沿用上一小时的分）。
- 未选中滚轮项颜色更浅；选中仅靠字重 / 字号，无底色块。

### 2.3 确定与拦截

- 确定时只提交当前选中的**一个**开始时间。
- 列表 / 先买后约：半屏①未选时间点「确认」→ Toast「请选择预约服务时间」，不关闭半屏。
- 订单页：未选上门时间点支付 → Toast「请先选择上门时间」。

### 2.4 客服

仅在「需要比尽快更早」时引导联系客服（黄条 / 预约说明内链接），不在其它位置强塞。

## 3. 使用场景

### 3.1 场景 A：列表预约（已买未约）

**入口**：订单列表「待预约」→「去预约」

```
去预约
  → 半屏①「预约服务」
      → 点「预约服务时间」
          → 半屏② 选时（默认日期 Tab）
              → 确定 → 回填半屏①
                  → 确认 → 预约成功（按钮可变为「已约」）
```

#### 半屏① 预约服务

| 元素 | 说明 |
| --- | --- |
| 标题 | 预约服务（右上关闭） |
| 剩余次数 | 展示剩余可约次数 |
| 预约服务时间 | 未选：`请选择 >`；已选：回填文案 + `>` |
| 说明文案 | `最快约30分钟上门。更早请联系客服` |
| 取消 / 确认 | 未选时间确认 → Toast：`请选择预约服务时间` |

半屏高度约 **48%** 屏高：内容置顶，按钮贴底（对齐现网比例）。

### 3.2 场景 B：订单页预约（立即预约）

**入口**：下单页「上门时间」→ **直接**打开半屏② → 确定后回填上门时间行。

选时规则与半屏②一致。选中尽快项时回填可用绿色强调。

### 3.3 场景 C：先买后约（支付成功页）

**入口**：支付成功页 → 已购服务「去预约」

| 区域 | 说明 |
| --- | --- |
| 成功头图 | 勾选 +「支付成功」+「请尽快完成服务预约」 |
| 已购服务 | 「已购服务（共 N 项）」；卡片含待预约次数、橙色「去预约」 |

之后流程、半屏①②、文案、拦截与场景 A **完全一致**。

## 4. 选择上门时间（半屏②）· 交互规格

三入口共用；高度约 **68%** 屏高。

### 4.1 结构（上→下）

1. **黄底 i 提示条（贴半屏顶，无上方白缝）**  
   `最快约30分钟上门，可在下方选择。更早请联系客服`
2. **日期 Tab | 时间 Tab** + 右侧「确定」
3. **日历** 或 **时分滚轮**

### 4.2 原则

- 一套日期 + 时间选择；尽快并进当天滚轮，**无**「尽快 / 指定时间」二选一卡片。
- 打开默认**日期**；当前 Tab 深色 + 下划线，另一侧 Tab **浅色**。
- 比尽快更早只走客服。

### 4.3 用户怎么选

```
打开半屏②
  → 默认：今天 + 日期 Tab（日历）
       时间 Tab 浅色显示默认时刻（尽快，如 16:23）
  → 可直接点「确定」→ 尽快上门 · HH:mm
  → 或点时间 Tab → 滚轮（尽快项带 ⚡）→ 可改半点 → 确定
  → 或改日期后再选时间 → 确定 → 日期 + 时刻
  → 若需更早 → 联系客服
```

| 行为 | 规则 |
| --- | --- |
| 打开 | 今天；默认时刻 = 尽快；**先展示日期 Tab**；时间 Tab 浅色 |
| 切到时间 | 滚轮落在当前选中时刻；当天首项为尽快 + ⚡ |
| 当天滚轮 | `16:23`⚡ → `16:30` → `17:00`…；可滚离尽快，不强制 |
| 其它日期 | 00:00–23:30 半点；换日尽量保留时:分 |
| 日历 | 周一起算；仅可从今天所在月往下翻；当月首行不展示上月日；过去日不可点 |
| 滚轮交互 | 时 \| 分两列；换小时落该小时最早项；选中项居中对齐选框 |
| 确定回填 | 尽快项 → `尽快上门 · 16:23`；否则 → `YYYY年M月D日 HH:mm` |

列表 / 先买后约：确定后回填半屏①。订单页：回填上门时间行。点遮罩关闭半屏②（若从半屏①进入，仍留在半屏①）。

## 6. 异常与边界

| 情况 | 处理 |
| --- | --- |
| 未选时间点确认 | Toast 拦截，不关闭半屏① |
| 需要比尽快更早上门 | 仅「联系客服」，无自助更早时段 |
| 尽快未跨日 | 当天：尽快 + 其后半点；其它日全天半点 |
| 尽快已跨日（如现在 23:50 → 尽快次日 00:20） | 默认落在尽快项；日历上**今天整日置灰不可点**；最早可约日为次日，该日滚轮为尽快精确时刻 + 其后半点；再之后日期全天半点 |
| 选未来日再切回今天 | 当天滚轮恢复为尽快 + 其后半点；原时分不可用则落到当天最早可约项 |

## 7. 数据与接口（实现建议）

| 字段 | 说明 |
| --- | --- |
| `book_mode` | `asap` \| `scheduled` |
| `start_time` | 业务时间戳；asap 为 +30′ 精确时刻；scheduled 为所选半点（或非 asap 的精确展示时刻） |
| `service_address_type` | `in_hospital`（本需求仅院内） |

服务端校验：

- 院内 asap：符合当前时刻 +30′ 规则；
- scheduled：半点合法；当天不得早于「尽快时刻」（除 asap 项本身）。

## 8. 验收标准

1. 打开半屏②：默认今天 + **日期 Tab**；时间 Tab **浅色**显示现在+30′；无「尽快」重推卡片。
2. 黄条贴半屏顶：文案为「最快约30分钟上门，可在下方选择。更早请联系客服」。
3. 点时间 Tab：当天滚轮含尽快精确时刻（旁极弱 ⚡）及之后半点；未选项更浅。
4. 选中尽快确定 → `尽快上门 · HH:mm`；选半点 → 日期 + 时刻。
5. 其它日期 00:00–23:30；换日尽量保持原时分。
6. 列表：去预约 → 半屏① → 选时 → 回填 → 确认；未选时 Toast「请选择预约服务时间」。
7. 先买后约：支付成功 → 去预约 → 与列表一致。
8. 订单页：上门时间直接进半屏②，规则同上。
9. 「更早」仅联系客服；无「推荐」标签。
10. 滚轮选中项在中间选框内居中；⚡ 不破坏 23 / 30 数字对齐。
