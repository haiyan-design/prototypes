## 1. 背景与目标

### 1.1 背景

院内场景上门时效更短，用户常有「尽快」诉求。若仍沿用偏长的最早可约逻辑，转化与体验都会受损。需要在院内提供明确的「尽快上门」能力，并保留按日期/半点预约。

### 1.2 目标

1. 院内默认引导「尽快上门」，提升近约转化。
2. 时间规则清晰：尽快为精确时刻；指定时间为半点。
3. 比尽快更早的需求走客服，不开放更早自助时段。
4. 三类入口时间规则一致：列表预约、订单页立即预约、先买后约（支付成功页）。

### 1.3 非目标

- 不改变院外预约时效与默认逻辑。
- 不开放「比尽快更早」的自助可选时段。
- 预约结果只存**一个开始时间**（非整段区间）。

---

## 2. 核心规则

### 2.1 尽快上门


| 项     | 规则                                          |
| ----- | ------------------------------------------- |
| 计算    | `尽快时刻 = 当前时间 + 30 分钟`（保留到分钟，不凑半点）           |
| 展示    | `尽快上门 · HH:mm`（例：现在 15:53 → `尽快上门 · 16:23`） |
| 落库/回填 | 单个开始时间，文案可用 `尽快上门 · 16:23`                  |
| 默认    | 打开「选择上门时间」半屏时，**默认选中尽快**                    |


### 2.2 指定时间（半点）


| 场景       | 可选半点                                  |
| -------- | ------------------------------------- |
| **当天**   | 从「尽快之后的第一个半点」起，至 23:30（`:00` / `:30`） |
| **其它日期** | 全天 00:00–23:30，无营业时段限制                |


示例（现在 15:53，尽快 16:23）：

- 当天半点从 **16:30** 起：16:30、17:00、17:30…
- 选中其它日期后，滚轮可出现更早半点（如 00:00、08:00）；**换日期时尽量保留当前选中的时:分**，不强制跳到最早。

换小时时：落到该小时**最早可选半点**（如从 16:30 滑到 17 → 默认 17:00，不沿用 :30）。

### 2.3 互斥与确定

- 「尽快」与「指定时间」**二选一**，确定时只提交一种结果。
- 不允许「两个都不选」仍可确定（列表 / 先买后约的「预约服务」半屏未选时间时拦截）。

### 2.4 客服入口

仅在表达「需要比尽快更早」时引导联系客服，不在其它位置强塞客服。

## 3. 使用场景与流程

### 3.1 场景 A：列表预约（已买未约）

**入口**：订单列表「待预约」→「去预约」

```
去预约
  → 半屏①「预约服务」
      → 点「预约服务时间」
          → 半屏②「选择上门时间」
              → 确定 → 回填半屏①
                  → 确认 → 预约成功
```

#### 半屏① 预约服务


| 元素      | 说明                           |
| ------- | ---------------------------- |
| 标题      | 预约服务（右上关闭）                   |
| 剩余次数    | 展示剩余可约次数                     |
| 预约服务时间  | 未选：`请选择 >`；已选：回填文案 + `>`     |
| 说明文案    | `院内最快30分钟上门。若需更早，请联系客服`      |
| 取消 / 确认 | 确认前若未选时间 → Toast：`请选择预约服务时间` |


半屏高度约 **48%** 屏高：内容置顶，按钮贴底，中间留白（对齐现网半屏比例）。

#### 半屏② 选择上门时间

见第 4 节。

### 3.2 场景 B：订单页预约（立即预约）

**入口**：下单页「上门时间」→ 直接打开半屏②「选择上门时间」→ 确定后回填上门时间行。

规则与列表半屏②一致。

### 3.3 场景 C：先买后约（支付成功页）

**入口**：支付成功页 → 已购服务卡片「去预约」

**页面结构（对齐现网截图）**


| 区域   | 说明                               |
| ---- | -------------------------------- |
| 成功头图 | 勾选图标 +「支付成功」+「请尽快完成服务预约」         |
| 已购服务 | 标题「已购服务（共 N 项）」                  |
| 服务卡片 | 服务名、待预约次数（如「待预约 **2次**」）、橙色「去预约」 |


**预约流程**（与场景 A 相同）

```
去预约
  → 半屏①「预约服务」（剩余次数等取自该已购服务）
      → 点「预约服务时间」
          → 半屏②「选择上门时间」
              → 确定 → 回填半屏①
                  → 确认 → 预约成功（按钮可变为「已约」）
```

半屏① / 半屏② 的字段、文案、拦截与选时规则与场景 A **完全一致**（含「院内最快30分钟上门…」与尽快/指定时间互斥）。

## 4. 选择上门时间 · 交互规格

半屏②统一组件，列表 / 订单页 / 先买后约共用；高度约 72% 屏高。

**页面结构（上→下）**

1. 标题「选择上门时间」+「确定」
2. 单选项「尽快上门 · HH:mm」（圆点单选，选中时展开「院内最快约30分钟上门」）
3. 「若需更早，请联系客服」
4. 单选项「预约指定时间」（圆点单选；尽快选中时下方日期/滚轮弱化，点该选项即可进入）
5. 指定时间选中后：日期 Tab | 时间 Tab → 日历或时分滚轮

**原则：** 尽快与预约指定时间是**两条单选**，不是可空勾。打开默认尽快；要离开尽快，点「预约指定时间」即可（不必再加「去选择」一类重复入口）。再点尽快可切回。右侧时间 Tab 只显示自选半点。比尽快更早只走联系客服，无「推荐」。

### 用户怎么选

```
打开 → 默认【尽快】 ──确定──▶ 尽快上门 · HH:mm
              │
              │ 点「预约指定时间」或进入后操作日期/滚轮
              ▼
         【预约指定时间】 ──确定──▶ YYYY年M月D日 HH:mm
              │
              └─ 再点「尽快上门」可切回（还要再点一次确定才提交）
```

- **打开：** 默认选中「尽快上门」（现在+30′）。下方「预约指定时间」未选中，日期/滚轮弱化不可点；可直接确定交尽快。
- **改成指定时间：** 点「预约指定时间」单选项（进入后可再点日期/时间/日历/滚轮）→ 尽快圆点取消，指定时间圆点选中并高亮。当天默认半点 = 尽快后第一个半点；换其它日期则 00:00–23:30，尽量保留原时:分。
- **切回尽快：** 再点「尽快上门」→ 尽快选中、日期回今天、指定时间区再弱化；半屏不关，需再点确定才提交。
- **日期 / 时间 Tab：** 仅在指定时间选中后可操作；日期对应日历，时间对应滚轮。

### 日历、滚轮与回填

- **日历：** 周一起算；从今天所在月起只可往下看后续月，不能往前看更早月；当月首行不展示上月数字；过去日不可点；尽快模式下不画选中圆点。
- **滚轮：** 时 | 分（00/30）；滑停以选中框内为准；换小时默认该小时最早半点（如 16:30→17 为 17:00）；选中项居中对齐选框。
- **确定：** 尽快 → `尽快上门 · 16:23`；指定时间 → `2026年10月29日 17:00`。列表/先买后约回填半屏①后再确认；订单页直接回填上门时间。点遮罩关闭半屏②（若从半屏①进入则仍留在半屏①）。

## 6. 异常与边界


| 情况             | 处理                                             |
| -------------- | ---------------------------------------------- |
| 未选预约服务时间点确认    | Toast 拦截，不关闭半屏                                 |
| 需要比尽快更早上门      | 仅「联系客服」，无自助更早时段                                |
| 跨自然日（接近 24:00） | 尽快 = 现在+30′（可跨日）；当天半点列表按「尽快之后」生成；实现需与服务端对齐跨日展示 |
| 选未来日再切回今天      | 半点列表恢复为「尽快后」；若原时分在当天不可用，落到当天最早可约半点             |

## 7. 数据与接口（实现侧建议）

提交字段建议：


| 字段                     | 说明                                        |
| ---------------------- | ----------------------------------------- |
| `book_mode`            | `asap`                                    |
| `start_time`           | ISO 或业务时间戳；asap 为计算后的精确时刻；scheduled 为所选半点 |
| `service_address_type` | `in_hospital`（本需求仅院内）                     |


服务端需校验：院内 asap 符合 +30′ 规则；scheduled 符合半点及「当天不得早于尽快后首个半点」。

## 8. 验收标准（摘录）

1. 打开选时半屏，默认尽快，展示现在+30′ 的精确时刻。
2. 尽快与指定时间互斥；尽快选中时日历无选中点、指定区弱化。
3. 点日期/时间后尽快取消，当天默认半点为尽快后第一个半点。
4. 其它日期半点为 00:00–23:30；换日尽量保持原时分。
5. 列表：去预约 → 预约服务 → 选时 → 回填 → 确认；未选时提示「请选择预约服务时间」。
6. 先买后约：支付成功页 → 去预约 → 后续与列表一致（半屏①②、文案、拦截）。
7. 订单页：上门时间直接进半屏②，规则同选时规格。
8. 「若需更早」入口可联系客服；无「推荐」标签。
9. 时分滚轮选中项在中间选框内居中。
