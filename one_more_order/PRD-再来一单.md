# PRD：e护通「再来一单」

| 项 | 内容 |
|---|---|
| 产品 | e护通 |
| 需求名 | 再来一单（引导复购 + 预填下单） |
| 版本 | V1.0 |
| 状态 | 原型已出 |
| 目标 | 在订单关键路径增加「再来一单」，一键带入原单关键信息进入预填下单，缩短决策路径，提升复购转化 |

---

## 1. 背景与目标

用户完成服务或服务进行中时，常有「再约一次」诉求，但现有路径需重新选服务 / 地址 / 被护理人，决策成本高。

**本期目标**

1. 在关键场景露出「再来一单」入口  
2. 点击后进入预填下单页，自动带入原单信息，可改可付  
3. 确认支付后拉起支付方式面板完成支付  

**成功指标（建议）**

- 「再来一单」点击率  
- 预填页支付转化率  
- 复购订单占比  

---

## 2. 范围

### 2.1 本期做

| 场景 | 页面 | 入口形态 |
|------|------|----------|
| 服务已完成（未评 / 可评） | 订单详情 | 底栏主按钮「再来一单」 |
| 评价完成 | 订单详情 | 底栏主按钮「再来一单」 |
| **已取消订单** | 列表 + 详情 | 列表卡片：联系客服右侧深色「再来一单」；详情底栏主按钮 |
| **退款成功** | 列表 + 详情（未预约 / 已预约两种） | 列表同上；详情底栏「再来一单」（已预约详情去掉「重新预约」） |
| **待完成**（所有子单已完成但未入账） | 列表 + 详情 | 列表卡片：联系客服右侧深色「再来一单」；详情底栏主按钮 |
| 我的 | 我的订单卡片 | 最近一单引导条 +「再来一单」 |
| 预填下单 | 确认支付页 | — |
| 支付 | 支付方式弹层 | — |

### 2.2 本期不做

- 好评结果页（历史「图二·查看评价页」独立链路）暂不单独做；评价完成后统一走「评价完成·订单详情」  
- 「仅此人可约 / 等此人有空」强指定能力（本期仅为优先偏好，约不上可改派）  
- 优惠券 / 营销自动带入规则细化

## 3. 预填规则（核心）

点击「再来一单」后，按**入口对应订单**预填，字段均可改。

| 入口 | 预填来源 |
|------|----------|
| 服务已完成·订单详情 | 当前该完成单 |
| 评价完成·订单详情 | 当前该已评价单 |
| 已取消订单·列表卡片 | 该取消单 |
| 已取消订单·订单详情 | 当前该取消单 |
| 退款成功·列表卡片 | 该退款成功单 |
| 退款成功·订单详情 | 当前该退款成功单 |
| 待完成·列表卡片 | 该待完成单（所有子单已完成但未入账） |
| 待完成·订单详情 | 当前该待完成单 |
| 我的·订单卡片 | **最近一次订单**（含已完成 / 已评价 / 已取消 / 退款成功 / 待完成等，取时间最近一笔有效单） |

**默认预填字段**

- 服务地址（含联系人 / 电话）  
- 被护理人  
- 服务项目、时长 / 规格、数量  
- 已选规格（如性别要求、人员等级加价等）  
- **优先服务人员**（展示本单 / 原单对应服务人员，**默认不勾选**；用户可勾选或更换为其他历史人员）  
- 价格按当前规则重算（以预填页展示为准）  

**不预填 / 需用户重选**

- 预约具体服务时间（若商品为「先买后约」则按原流程；若需立即预约则进入对应预约步骤）  
- 支付方式（每次重新选择）  

**优先服务人员规则**

**是否展示**

| 条件 | 处理 |
|------|------|
| 至少 1 名**业务可用**历史人（未离职 / 未拉黑 / 可接单等） | **展示**「优先服务人员」模块 |
| 0 名业务可用，或品类不支持指定人员 | **整块不展示、不提醒**；不传人员偏好，平台按规格派单 |

说明：改规格导致「当前无人匹配」时**不隐藏**模块（走冲突路径：取消勾选，卡片仍留人；半屏内不符项置灰）。显隐只跟业务可用人数 / 品类开关有关，不跟规格瞬时匹配结果挂钩。

**展示时**

- 可勾选 = 业务可用且与当前规格（性别、人员等级）不冲突  
- 只展示 **1 名推荐人员**：优先本单服务人（若其可勾选）；否则在可勾选中取服务次数最多 / 最近上门；若当前规格下暂无可勾选，卡片仍展示原推荐人（未勾选）  
- **原单人不可用但有其他人**：静默推荐其他人，**不提示**「原人不可约」，半屏不展示不可用原人  
- 交互：进入页默认不勾选；可勾选 / 取消；不勾选 = 不传人员偏好，走平台派单  
- 「更换」进入半屏：仅列出业务可用的历史人（规格不符置灰）+「不指定，由平台安排」  
- **必达告知**（已勾选时）：将优先安排该人员；若其时间冲突或暂不可接单，安排同等条件其他人员  
- **未勾选时告知**：当前不优先指定，将由平台按您的服务要求安排；可勾选或点「更换」选择历史服务人员  
- 支付成功仅落库「人员偏好」；档期是否可约在预约 / 派单环节再校验  

#### 规格与优先人员冲突（性别 / 人员等级）

**总原则**

- 冲突时：静默纠正 + Toast；**不弹窗确认、不阻断改规格、不阻断支付**  
- 文案写清是「性别」还是「人员等级」；两项均不符时**并列写清**，**禁止**写成「性别/等级」  
- **按操作顺序**决定句式：用户刚动的是什么，Toast 就回应什么  
- 取消勾选后人员卡片**仍展示该人**，不改成「未指定」空态  

**匹配判定**（与现网派单规则对齐）

| 规格项 | 判定 |
|--------|------|
| 性别要求 = 不限 | 不校验性别 |
| 性别要求 = 男 / 女 | 人员性别必须一致，否则 **性别冲突** |
| 人员等级 | 人员等级必须与当前所选等级一致，否则 **人员等级冲突** |

---

**路径 A：先选规格，再点「优先服务人员」勾选**（尚未勾选成功）

系统：**不勾选**；Toast 用「与当前…不符，请修改 / 更换」句式（**不写**「已取消优先指定」）。

| 不符情况 | Toast |
|----------|-------|
| 仅性别不符 | 「{姓名}」与当前性别要求不符，请修改性别或点「更换」选择其他人 |
| 仅人员等级不符 | 「{姓名}」与当前人员等级要求不符，请修改人员等级或点「更换」选择其他人 |
| 性别与人员等级均不符 | 「{姓名}」与当前性别要求、人员等级均不符，请修改规格或点「更换」选择其他人 |
| 均符合 | 正常勾选，无 Toast |

---

**路径 B：先勾选优先人员，再改规格**（取消已勾选）

系统：**立刻取消勾选**；卡片仍展示该人；价格按新规格重算；Toast 用「因…不符，已取消优先指定」句式。

| 操作 | Toast |
|------|-------|
| 只改性别 → 冲突 | 因性别要求与「{姓名}」不符，已取消优先指定，将由平台安排 |
| 只改人员等级 → 冲突 | 因人员等级要求与「{姓名}」不符，已取消优先指定，将由平台安排 |
| 一次校验两项均冲突（如支付兜底） | 因性别要求、人员等级均与「{姓名}」不符，已取消优先指定，将由平台安排 |
| 已因冲突取消勾选后，继续改另一规格（仍未勾选） | **不再弹 Toast**，避免刷屏 |
| 改规格后仍匹配 | 保持勾选，无 Toast |

说明：路径 B 下「只改一项」时，Toast **只写该项原因**（不提未改动的另一项）。

---

**路径 C：「更换」半屏**

- 不符人员：**置灰不可选**  
- 行内标注（已说明原因，**不再 Toast**）：  

| 不符情况 | 半屏标注 |
|----------|----------|
| 仅性别 | 性别不符 |
| 仅人员等级 | 人员等级不符 |
| 两项均不符 | 性别、人员等级不符 |

- 点击置灰项：**不选中、无 Toast**（避免与行内标注重复打扰）  

---

**路径 D：支付前兜底**

- 点击「立即支付」前再校验  
- 仍勾选且冲突：取消勾选 + Toast（按当前全部不符项写清；两项均不符则并列）  
- **允许继续支付**（按不指定人员下单）  

---

**一句话规则**

1. **路径 A（未勾选 → 点勾选）**：拦截；「与当前…不符，请修改/更换」；几项不符写几项；**不写「已取消优先指定」**。  
2. **路径 B（已勾选 → 改规格）**：取消勾选；「因…不符，已取消优先指定」；只写**本次改动触发**的原因。  
3. **路径 C（更换半屏）**：置灰 + 行内标注；**半屏内不弹 Toast**。  
4. **路径 D（支付前）**：再校验；两项均冲突则并列写清；不阻断支付。  

**不做**

- 不因冲突禁止修改规格  
- 不弹「是否取消优先」确认框  
- 不因规格冲突自动换成另一名匹配人员（须用户主动「更换」；与「原人不可用静默换推荐」不同）  
- 不因人员偏好冲突阻断支付  
- 半屏不符项不重复 Toast（已有行内标注）  
- 落到只能平台安排时：不展示「平台安排」空卡片、不弹原人不可约类提醒

## 4. 分场景页面说明

写法约定：有列表与详情的场景，统一按 **「列表页 + 详情页 + 交互」** 合并书写。仅详情入口的场景（服务已完成、评价完成）只写详情。

### 4.1 服务已完成（详情）

**场景名**：服务已完成（未评 / 可评）。本期仅详情入口，无单独列表改造。

**详情页**

- 状态区标题：服务已完成（**无副文案**）  
- 评价卡片：护工头像、「您对我满意吗？」、匿名、护工名 / 评分、五档满意度  
- 订单信息、服务商品与金额  
- 底栏：联系客服 | **再来一单**（实心主色，深色引导）  

**交互**

| 操作 | 结果 |
|------|------|
| 点满意度表情 | 进入 / 展开评价填写（现网；原型仅入口态） |
| 详情点「再来一单」 | 预填本单 → 预填下单页 |
| 点联系客服 | 客服会话（现网） |

**相对旧版**：去掉状态区 / 底栏「去评价」；评价在页内；「再次预约」统一为「再来一单」。

---

### 4.2 评价完成（详情）

**场景名**：评价完成。本期仅详情入口。

**详情页**

- 状态区标题：已评价  
- 评价结果卡：头像、「感谢您的评价」+ **「查看」**、护工名 / 评分  
- 订单信息、商品与金额（同完成态）  
- 底栏：联系客服 | **再来一单**（实心主色）  

**交互**

| 操作 | 结果 |
|------|------|
| 点「查看」 | 进入评价详情（现网） |
| 详情点「再来一单」 | 预填本单 → 预填下单页 |

**相对旧版**：去掉底栏「查看评价」，改为「再来一单」。

---

### 4.3 已取消订单（列表 + 详情）

**场景名**：已取消订单。

**列表页**

- 订单卡片状态文案：已取消  
- 操作区：联系客服（描边）| **再来一单**（实心深色，在联系客服**右侧**）  

**详情页**

- 状态区标题：已取消  
- 底栏：联系客服 | **再来一单**（实心深色主按钮）  

**交互**

| 操作 | 结果 |
|------|------|
| 列表点「再来一单」 | 预填该取消单 → 预填下单页 |
| 详情点「再来一单」 | 预填当前取消单 → 预填下单页 |

**说明**：取消单无成功服务体验，再来一单定位为「重新下单」；优先服务人员仍展示、默认不勾选（与预填页一致）。

---

### 4.4 退款成功（列表 + 详情）

**场景名**：退款成功。

**列表页**

- 订单卡片状态文案：退款成功  
- 操作区：联系客服（描边）| **再来一单**（实心深色，在联系客服**右侧**）  

**详情页（两种）**

1. **未预约详情**：提示「您还没有开始预约」；底栏联系客服 | **再来一单**  
2. **已预约详情**：展示上门时间；子单区**不展示「重新预约」**（仅联系客服）；底栏联系客服 | **再来一单**  

**交互**

| 操作 | 结果 |
|------|------|
| 列表点「再来一单」 | 预填该退款成功单 → 预填下单页 |
| 未预约 / 已预约详情点「再来一单」 | 预填当前单 → 预填下单页（新单，非改约） |

**说明**：与已取消类似；**退款中**不出再来一单。已预约场景用「再来一单」替代「重新预约」。

**附加**：订单详情页点击服务商品区（图 / 标题）→ 进入该服务商详页（可返回订单详情）。

---

### 4.5 待完成（所有子单已完成但未入账 · 列表 + 详情）

**场景名**：待完成 · 所有子单已完成但未入账。

**列表页**

- 订单卡片状态文案：待完成  
- 操作区：联系客服（描边）| **再来一单**（实心深色，在联系客服**右侧**）  

**详情页**

- 状态区标题：待完成  
- 可含服务记录（已评价 / 查看评价等），底栏：联系客服 | **再来一单**（实心深色主按钮）  

**交互**

| 操作 | 结果 |
|------|------|
| 列表点「再来一单」 | 预填该待完成单 → 预填下单页 |
| 详情点「再来一单」 | 预填当前待完成单 → 预填下单页 |

**说明**：所有子单已服务完成，整单尚未入账完结；再来一单按该单预填，不替代本单入账 / 完结。页内状态仍展示「待完成」。

---

### 4.6 我的 · 订单卡片

**位置**：我的 →「我的订单」模块，状态入口行下方。

**引导条内容**

- 左侧：最近一单服务缩略图  
- 文案：`服务状态 / 服务类型 / 价格`（例：`已完成 / 各种陪护项目 / ¥103.00`）；过长省略，**悬停可查看全文**  
- 右侧：「再来一单」按钮  

**交互**

| 操作 | 结果 |
|------|------|
| 点「再来一单」 | 预填**最近一次订单** → 预填下单页 |
| 点「全部订单」 | 进入订单列表 |
| 引导条文案过长 | 单行省略；悬停（或聚焦）浮层展示全文 |
| 无最近一单 | **不展示**引导条 |

---

### 4.7 预填下单页（确认支付）

**进入方式**：各场景「再来一单」。

**页面结构**

1. 服务地址、被护理人（可点进修改）  
2. 服务商品、数量步进、已选规格 +「修改」  
3. **优先服务人员**：展示本单推荐人员（**默认不勾选**）+ 告知文案 +「更换」  
4. 特殊补充 / 优惠券（选填入口；**随页面滚动**，在优先服务人员下方）  
5. **仅底栏固定**：协议勾选、合计、查看明细、**立即支付**  
（页面顶部不展示「已根据…预填」提示条）

**交互**

| 操作 | 结果 |
|------|------|
| 改地址 / 被护理人 | 进入选择页，回填后刷新价格 |
| 改数量 / 规格 | 价格重算；若与已勾选人员冲突：走 **路径 B**（见 §3） |
| 勾选 / 取消优先人员 | 取消勾选自由；勾选时若冲突走 **路径 A** |
| 点「更换」 | 半屏走 **路径 C**；可选「不指定」 |
| 立即支付 | 协议校验后走 **路径 D** 再拉支付 |
| 未勾选协议点立即支付 | Toast / 提示先同意协议 |
| 已勾选点「立即支付」 | **拉起支付方式弹层** |
| 返回 | 回原入口页 |

---

### 4.8 支付方式弹层

**触发**：预填页「确认支付」且已同意协议。

**结构**

- 保障说明：三包保障、过程留痕、持证上岗、极速维权  
- 关闭（×）  
- 支付方式（单选，默认微信支付）  
  - 微信支付  
  - 金币支付（展示 e护通金币余额）  
  - 好友代付  
- 温馨提示：如需发票，请在服务完成后联系客服  
- 合计 + **立即支付**  

**交互**

| 操作 | 结果 |
|------|------|
| 切换支付方式 | 单选高亮 |
| 点遮罩 / × | 关闭弹层，停留预填页 |
| 点「立即支付」 | 调起对应支付；成功 → 支付成功 / 订单详情；失败 → 提示可重试 |

## 5. 主流程

```
各场景点击「再来一单」
    → 预填下单页（带入对应订单信息；展示本单服务人员，默认不勾选优先）
    → 用户可修改地址 / 被护理人 / 规格 / 勾选或更换优先人员
    → 勾选协议 → 立即支付
    → 支付方式弹层 → 立即支付
    → 支付成功，生成新订单（含人员偏好标记，若有）
    → 预约 / 派单时优先匹配该人员；不可用则同等条件改派并告知
```

## 6. 异常与边界

| 情况 | 处理 | 原型入口（侧栏「异常与边界」） |
|------|------|------------------------------|
| 原服务已下架 / 不可售 | 列表 / 详情点「再来一单」弹窗（标题「提示」；正文「抱歉，原服务已下架，请重新选购。」；关闭 × / 好的 / 选购），不进预填页 | 列表 `?edge=sku-off`；详情 `?edge=sku-off` |
| 原地址不存在 | 顶部提示「原地址不存在，请重新选择服务地址后再支付。」；地址栏清空，由用户点击重选 | `?edge=addr-missing` |
| 被护理人已删除 | 顶部提示「原被护理人已删除，请重新选择后再支付。」；被护理人栏清空，由用户点击重选 | `?edge=patient-bad` |
| 原服务人员不可用，但仍有其他可勾选历史人 | 静默推荐其他人（默认不勾选）；不提示原人不可约；半屏不含原人 | `?edge=staff-gone` |
| 无可选历史人员 / 品类不支持指定 | 整块「优先服务人员」不展示、不提醒；直接平台派单 | `?edge=staff-none` |

## 8. 验收标准

1. 各场景入口（完成 / 评价 / 已取消 / 退款成功 / 待完成 / 我的）均可进入预填页，且预填来源符合第 3 节规则  
2. 服务已完成页：无「去评价」底栏入口；无「本次服务已完成，感谢您的信任…」副文案；有页内评价区 +「再来一单」  
3. 评价完成页：无底栏「查看评价」；有「感谢您的评价」旁「查看」；底栏为「再来一单」  
4. 确认支付拉起支付弹层，默认可完成「立即支付」主路径演示  
5. 样式比例、图标风格对齐现网截图，避免花哨装饰图标
