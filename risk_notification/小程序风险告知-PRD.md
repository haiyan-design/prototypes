# 小程序「平台交易须知 / 风险提示」PRD

| 项 | 内容 |
|----|------|
| 文档名称 | 小程序风险告知 |
| 产品 | e护通（居家护理 / 护工服务）小程序 |
| 版本 | V1.0 |
| 状态 | 方案已定（下单页采用弱化） |
| 原型 | `小程序风险告知.html`（入口） |

---

## 1. 背景与目标

### 1.1 背景

平台存在服务人员诱导用户**取消订单后私下交易、微信/支付宝转账**等行为。用户一旦脱离平台，售后介入、资金退赔、身份核验与保险链路难以保障，纠纷处理成本高。

### 1.2 目标

- 在关键决策节点提示「通过平台交易」的边界与风险，降低线下交易发生率。
- 控制提示强度，避免警告疲劳、不影响核心转化（尤其下单支付）。
- 与现有「权益保障」心智区分清楚：权益讲「平台内有什么」，须知讲「离开平台会怎样」。

### 1.3 成功指标（建议）

- 取消订单场景中，与「诱导私下交易」相关的客服进线可标记率提升。
- 下单转化率无明显负向（弱化方案优先保障转化）。
- 「一键举报 / 联系客服」在电话、取消等节点的点击率可观测。

---

## 2. 范围

### 2.1 本期包含

| 场景 | 形态 | 说明 |
|------|------|------|
| 商详页 | 权益半屏内短提示 + 可展开 | 嵌在「权益保障」末尾 |
| 下单页 / 购物车下单页 | **弱化常显提示** | 支付栏上方，贴协议 |
| 打电话（订单详情） | 居中轻弹窗「风险提示」 | 点电话后、呼叫前 |
| 取消订单（文案与路径建议） | 取消弹层内风险提示 | 见第 6 节；若本期仅改文案可单列排期 |

### 2.2 本期不包含

- 独立「举报工单」系统（举报能力以**跳转客服**实现）。
- 下单页「完整黄底警示条」方案（仅作对照，**不采用**）。

---

## 3. 总体原则

1. **高危行为前强提醒，浏览/支付前轻提醒**  
   电话、取消 > 下单支付 > 商详了解权益。
2. **同一话术体系，不同强度**  
   核心信息一致：勿私下转账、勿取消后线下交易；平台无法保障售后与纠纷。
3. **不与价差说明抢位**  
   合计旁「i」专用于「最终支付价格会因服务地点不同有所差异」，风险提示不使用该气泡。
4. **不强制勾选风险须知**  
   协议勾选仍只服务《平台服务协议》；风险为告知，不增加第二道强制勾选。

---

## 4. 分场景需求

### 4.1 商详页（服务详情）

#### 入口

- 现有绿色权益条：三包保障 / 过程留痕 / 持证上岗 / 极速维权。
- 点击打开半屏，标题：**权益保障**。
- **默认不自动弹出**半屏。

#### 半屏内容结构

1. **原有权益四块**（保持现网结构与文案主体，可不改业务含义）。
2. **底部短边界提示**（收起态，常显在权益内容下方）：
   - 左侧：**三角感叹号**警示图标。
   - 文案：  
     > 以上保障仅适用于通过平台下单并支付的订单。若私下转账，或取消订单后线下交易，平台将无法保障售后与纠纷处理。
   - 操作：**了解更多**（半屏内展开，**不跳转下单页**）。
3. **展开后「平台交易须知」**（与下单页完整说明一致，见附录 A）：
   - 独立于短提示的卡片区域；
   - 展开后短提示**完全隐藏**（避免与须知正文重复）；
   - 内容：售后难保障、资金无保障、人身与财产风险 + 行动提示；
   - **「收起」放在须知内容底部**（看完即可收，无需滑回顶部；收起后短提示恢复显示）。
4. **无「我知道了」按钮**；关闭方式：右上角关闭、点击遮罩。

#### 验收要点

- [ ] 进入商详不自动弹出权益半屏。
- [ ] 短提示前有三角感叹号。
- [ ] 「了解更多」在半屏内展开为独立须知卡片；「收起」在内容底部。
- [ ] 展开后短提示完全不显示；收起后恢复。
- [ ] 不跳转到下单页。

---

### 4.2 下单页 / 购物车下单页（采用弱化）

#### 决策说明

页面信息已较多，且底部已有协议勾选、合计、价差「i」、支付按钮。黄底完整警示条过重，易显得更挤并与支付决策区抢注意力。  
**定稿：弱化方案。**

#### 位置

- 固定在底部支付栏内，**协议勾选上方**。
- 不占用合计旁气泡位。

#### 样式与内容

- **无黄底色块、无感叹号/圆形 i 图标**（避免与合计旁价差「i」冲突）。
- 灰色短文案 + 「了解更多」文字链：  
  > 请通过平台下单支付，勿私下转账  
  > **了解更多**
- 点击整行或「了解更多」→ 半屏标题：**平台交易须知**（内容见附录 A）。
- 半屏**无「我知道了」**；关闭方式：右上角关闭、点击遮罩。

#### 涉及页面

- 服务下单页（含先买后约 / 立即预约等）。
- 购物车确认支付页。

两页交互与文案保持一致。

#### 验收要点

- [ ] 常显为弱化灰字一行，非黄底警示条。
- [ ] 无额外「!」或「i」图标。
- [ ] 可打开「平台交易须知」半屏，含 3 风险 + 1 行动。
- [ ] 价差「i」逻辑与文案不变。

---

### 4.3 打电话页（订单详情 · 联系服务人员）

#### 触发

用户点击服务人员卡片上的**电话**按钮后，在系统呼叫面板之前弹出。

#### 形态

- **居中轻弹窗**（非大半屏长文）。
- 标题：**风险提示**（本场景不用「平台交易须知」作标题，以降低通话前阅读负担）。

#### 文案

> 通话中请勿约定私下转账或取消后线下交易，平台无法保障售后。  
> （橙色）如遇诱导加微信收款，请使用「一键举报」向我们反馈。

#### 按钮

| 按钮 | 行为 |
|------|------|
| 取消 | 关闭弹窗，不发起呼叫 |
| 继续呼叫 | 关闭弹窗，进入现有系统呼叫面板（号码 / 呼叫 / 取消） |

#### 验收要点

- [ ] 点电话先出「风险提示」，确认后才出呼叫面板。
- [ ] 文案为短弹窗，无 3 条长列表。
- [ ] 标题为「风险提示」。

---

### 4.4 取消订单（建议同步，可同版本或紧随）

#### 问题（现状）

- 风险文案偏空泛（「拒绝任何形式线下交易」），未点明「**为私下交易而取消**」路径。
- 「如遇此情况」指代不清。
- 弹层内「一键举报」与底栏「确认取消」层级不清；且举报实际为**跳转客服**。

#### 文案建议

> 【风险提示】  
> 若服务人员要求您取消订单后私下交易或转账，请勿确认取消，并立即联系客服向我们反馈。私下交易无保障，纠纷难维权。

#### 举报路径（约束：只能跳转客服）

1. 按钮文案建议：**联系客服举报**（或「去客服反馈」），避免用户以为有独立举报页。
2. 跳转前可一句预期：将转接客服；请说明诱导取消 / 私下收款等。
3. 跳转时尽量带：订单号、来源「取消订单」、问题类型标记（若客服通道支持）。
4. 跳转前**收起取消弹窗**，从订单详情进客服；返回后可再次取消。
5. 不要「举报成功后自动取消订单」。

## 5. 文案对照（定稿）

| 场景 | 标题 / 形态 | 主文案 |
|------|-------------|--------|
| 商详短提示 | 权益半屏底部 | 以上保障仅适用于通过平台下单并支付的订单。若私下转账，或取消订单后线下交易，平台将无法保障售后与纠纷处理。 |
| 下单弱化常显 | 无标题一行 | 请通过平台下单支付，勿私下转账 |
| 下单 / 商详展开 | 平台交易须知 | 见附录 A |
| 打电话 | 风险提示 | 见 4.3 |
| 取消订单 | 风险提示 | 见 4.4 |

行动句统一口径（展开须知内）：

> 护工诱导取消订单、加微信私下收款等：请拒绝，并联系客服向我们举报。

打电话弹窗因页面已有「一键举报」，行动句可写「一键举报」；其余场景写「联系客服」。

## 6. 交互与异常

| 项 | 说明 |
|----|------|
| 半屏关闭 | 关闭按钮、点击遮罩（下单 / 商详均无「我知道了」） |
| 重复进入 | 每次进入下单页均常显弱化提示；商详半屏不自动弹出 |
| 打电话 | 每次点击电话均先出风险提示（不做「今日不再提示」，V1） |
| 客服不可用 | 跳转失败时 Toast 提示，引导稍后重试或电话客服（按现网能力） |

## 附录 A　平台交易须知（完整展开文案）

**标题：** 平台交易须知  

**副文案（可选）：**  
为保障您的资金与售后权益，请务必通过平台完成下单与支付。

1. **售后难保障**  
   加价、不到岗、服务质量等问题，脱离平台后难以介入取证与处理。

2. **资金无保障**  
   微信/支付宝等私下转账，退款与赔付需自行协商解决。

3. **人身与财产风险**  
   脱离平台后，身份核验、服务记录与保险链路可能不完整。

**行动：**  
如遇以下情况，请拒绝并举报：护工诱导取消订单、加微信私下收款等——请拒绝，并联系客服向我们举报。
