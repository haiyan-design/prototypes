# e护通 · 包月找人｜千人千面逻辑

> 包月找人是 e护通小程序里的一个功能。排序要用用户在小程序里已有的行为，不只看本功能里的备选和拨打。  
> 会员档是第一顺序。权重只排档内名次。999 只有病症明显更贴时，才能例外插进 3999 段，且插在第 3 位及以后。

---

## 一、总规则

无论进首页还是筛选之后，默认顺序都是：

```
先全部 3999（档内按权重从高到低）
再全部 999（档内按同一种权重从高到低）
```

- 3999 内部、999 内部，用同一套权重分。权重分不能把 999 整段抬到 3999 前面。
- 用户刚进来：不筛，先按上面的结构推（默认城市）。
- 用户筛选或帮我找：先按条件裁池，再对剩下的人用同一结构重排。
- 例外穿插见 5.4：只有下一位 3999 病症明显不贴、而某个 999 明显更贴时，才把这 1 个 999 插到第 3 位或更后。第 1、第 2 位仍是当前最贴的 3999。

---

## 二、和整站的关系

包月找人不是孤立推荐。权重要读用户在 e护通小程序里、进入本功能之前就已经发生的行为，例如：

| 整站行为 | 怎么用 |
|----------|--------|
| 搜索过某种病症 | 提高具备该病症技能的护工在档内的权重 |
| 下单过某种病症 / 相关服务 | 比「只搜索过」更强，同一病症技能再提高 |
| 浏览过相关服务、问诊或内容（若有） | 弱于下单，可作为同类病症的轻偏好 |

本功能内再生的行为继续叠加，但不能单独代表这个人：

| 本功能行为 | 怎么用 |
|------------|--------|
| 备选 | 同类病症、同区略加 |
| 拨打 | 此人可稍后；同类技能略加 |
| 采用 | 同类技能再加；此人本身不必反复顶到最前（已在「已联系」） |
| 反复点开不行动 | 略降 |

没有整站记录、也没有本功能记录的新用户：3999 仍整段在前，档内按资料完整度、年限、热度排。

## 三、两条路径（结构相同）

### 进首页（还没筛选）

```
默认城市 ∩ 可展示
    → 分成 3999 / 999
    → 各自按权重分降序
    → 3999 段 + 999 段
    → 若满足 5.4，把 1 个 999 插到第 3 位或更后
    → 分页（每页 10，页与页是同一条序列切开）
```

此时没有性别、预算等硬条件。病症倾向主要来自整站搜索、下单，以及本功能历史。

### 筛选或帮我找之后

```
按本次条件硬过滤（不符合的直接去掉）
    → 剩下的人再分成 3999 / 999
    → 各自仍按同一套权重分降序
    → 3999 段 + 999 段
    → 若满足 5.4，一屏最多再插 1 个 999
    → 从第 1 页重新展示
```

帮我找不是另一套算法，只是一次带上若干筛选条件，然后走这条路径。

筛选只决定谁还能出现。出现之后，仍然是 3999 优先，档内再比权重。

---

## 四、硬过滤（只在筛选 / 帮我找时）

| 条件 | 规则 |
|------|------|
| 城市 | 必须中（首页默认城市也算一道范围，不是「病症筛选」） |
| 区 | 选了具体区才限制 |
| 性别 | 有选则必须一致 |
| 病症 | 与护工技能有交集 |
| 预算 | 参考价落在区间内 |
| 年龄 / 等级 | 有选才限制 |
| 合规 | 下架、违规、拉黑不展示 |

过滤后没有人：提示放宽条件，不把池外的人塞回来。  
过滤后只有 999：就只展示 999，不编造 3999。

---

## 五、档内权重分（3999 和 999 同一套）

```
权重分 = 病症契合 + 地区契合 + 预算契合 + 资料与经验 + 热度
```

病症契合高于热度。热度满分 15 分，翻不过一次明确的病症命中。权重分不改变「先 3999 段、后 999 段」。999 进到 3999 中间只走 5.4 的例外。接通率本期不采集，不进权重。

各项只在「用得上」时计入。某一项没有信号时，把它的分数按比例摊回「资料与经验」和「热度」，不用中性分把所有人打成一样。

### 5.0 分数怎么拆（满分 100）

3999 与 999 用同一张表。先分成两段，再在段内按分从高到低排。

**首页（还没筛选）**

| 项 | 分 | 怎么打 |
|----|----|--------|
| 整站下单过的病症 | 28 | 护工主技能命中得 28；只命中相关技能得 17；未命中得 0 |
| 整站搜索过的病症 | 12 | 主技能 12，相关技能 7，未命中 0。已因下单得过病症分时，搜索不再重复加同一病症 |
| 本功能里的病症行为 | 10 | 采用过该病症 10，只拨打过 7，只备选过 4。同一病症取最高一档 |
| 地区 | 10 | 与历史订单同区 10，只是同城 4，没有区记录则此项不计、分数摊回 |
| 资料与经验 | 25 | 认证齐全最多 8，有介绍视频 5，从业年限最多 12（8 年及以上封顶） |
| 热度 | 15 | 采用率最多 10，备选率最多 5。规则见 5.3 |

没有下单、搜索、本功能病症记录时：病症这 50 分摊回资料与经验、热度（约七成给资料，三成给热度）。新人档内主要比资料、年限和热度。

**筛选或帮我找之后**

硬过滤已经去掉不符合的人。档内再打分：

| 项 | 分 | 怎么打 |
|----|----|--------|
| 本次病症 | 40 | 选了病症才计。主技能命中 40，只是相关技能 24。没选病症则这 40 分摊到下面各项 |
| 本次预算 | 15 | 落在区间中部 15，靠近两端 8。没选预算则摊回 |
| 本次地区 | 10 | 选了区且同区，池内大家都有这 10 分，不再拉开差距。没选区则按历史订单同区 10 / 同城 4 |
| 历史病症 | 10 | 整站下单命中且与本次不冲突 10；只搜索过 6；本功能里采用/拨打/备选过 4。与本次是同一个病症则不重复加 |
| 资料与经验 | 10 | 认证、视频、年限，按首页同一规则折到 10 分 |
| 热度 | 15 | 与首页相同：采用率 10，备选率 5 |

病症分已差 20 分及以上时，热度不得把低分的人排到前面。例：主技能命中（40）对只是相关技能（24），热度再高也仍是主技能在前。

### 5.1 病症契合（个性化的主体）

按证据从强到弱，取用户身上已有的病症偏好（可同时有多个，主偏好权重大）：

| 证据 | 强度 | 来源 |
|------|------|------|
| 本次筛选 / 帮我找选中的病症 | 最强 | 当前意图，压过历史 |
| 在 e护通下单过的病症或对应服务 | 强 | 整站，进入本功能之前就有 |
| 在 e护通搜索过的病症 | 中 | 整站 |
| 本功能里备选、拨打、采用过的病症 | 中 | 本功能 |
| 只浏览过相关内容 | 弱 | 整站或本功能 |

护工技能与上述偏好命中：主技能高于相关技能。  
本次筛选已经把病症滤死时，档内比的是「历史里还有没有第二病症、资料和热度」，而不是再把不合筛选的人加回来。

多个历史病症：下单过的优先于只搜索过的；次数多的优先；越近的优先（建议 30 天内权重大于更早）。

### 5.2 其他项

| 项 | 首页 | 筛选后 |
|----|------|--------|
| 地区 | 默认同城即可；若历史订单有区，同区略高 | 选了区则池内都已同区，此项拉平，比区以下的差异 |
| 预算 | 无选择则不计或仅按历史客单接近度略加 | 越靠近所选区间中部越高 |
| 资料与经验 | 认证齐全、有视频、年限高则加 | 同左 |
| 热度 | 见 5.3，采用率高于备选率 | 同左 |

### 5.3 热度（别人的备选率、采用率）

热度是供给信号，看的是**其他用户**对这个护工的备选和采用，不是当前用户自己有没有备选。

| 项 | 规则 |
|----|------|
| 采用率 | 档内次要项里更有用。先拨打再标记采用，比备选更能说明别人联系后愿意继续 |
| 备选率 | 可以加，权重要低于采用率。备选成本低，只在病症差不多时帮忙区分 |
| 用率不用绝对人数 | 曝光久的人备选数天然更高。率 = 行为人数 / 有效曝光人数 |
| 样本门槛 | 曝光或进入详情的人数不够时，这项先不计，避免一两个人就变成「很高」 |
| 新人 | 样本不够时热度为 0，不惩罚；靠资料、年限以及 3999 档本身露出 |
| 和火焰标 | 用同一套热度数据。达到展示门槛才在头像右下角出火焰，避免角标和排序各算各的 |
| C 端文案 | 不展示「多少人备选 / 多少人采用」 |

热度在两条路径、两个会员档里都算，算法相同。它改变的是档内名次，不改变「先 3999、后 999」。

### 5.4 999 何时可以出现在 3999 中间

默认不穿插。3999 病症已经贴合时，999 仍排在整段 3999 之后。

只有下一位 3999 的病症分比这名 999 低 20 分及以上，才把这 1 名 999 插进去，避免用户把一整屏不对症的 3999 直接滑走。

| 规则 | 说明 |
|------|------|
| 插几个 | 只插 1 个，取病症分最高的那名够格 999 |
| 插在哪 | 第 3 位或更后。第 1、第 2 位仍是当前病症最贴的 3999 |
| 筛选 / 帮我找 | 同样最多 1 个，条件更看本次选中的病症 |
| 被挤下的 3999 | 顺延到下一位，不掉到所有 999 后面 |

下面任一情况都不插，仍是先排完 3999 再排 999：

- 当前池里 3999 不足 6 人
- 没有病症分差距达到 20 分的 999
- 用户按价格排序：主序只按价格；同价时仍先 3999，再在同价里用权重分

## 六、同一用户会看到什么

| 情况 | 结果 |
|------|------|
| 新用户，上海，没筛过、没下过单 | 上海 3999 在前（档内比资料、年限、热度），然后上海 999 |
| 曾在小程序搜索/下单「脑梗」 | 3999 段内脑梗靠前；这些 3999 已经贴合时，999 仍在整段之后 |
| 下一位 3999 病症明显不贴，有 999 更贴 | 第 1、第 2 位仍是最贴的 3999；从第 3 位起插入这 1 名 999 |
| 筛选「女 · 浦东 · 8000–10000」 | 先裁池，再 3999 段、999 段；只有 5.4 满足时才在一屏里插 1 名 999 |
| 历史是脑梗，本次筛选肿瘤 | 以本次筛选为准先裁池；历史脑梗不再把肿瘤池外的人拉回来 |
| 该城市没有 3999 | 只出 999，档内照权重排 |

## 七、不参与这套排序的

| 页面 | 顺序 |
|------|------|
| 我的 · 备选 | 用户备选顺序，最多 3 人 |
| 我的 · 已联系 | 拨打 / 采用时间 |
| 详情 | 不排序；可显示技能与认证，不讲「算法」 |

已采用、已拨打的人如果仍在列表里：档内略靠后即可，不从 3999 段掉进 999 段。

## 八、空与降级

| 情况 | 处理 |
|------|------|
| 筛选后无人 | 提示放宽，不混入不符合的人 |
| 没有整站病症记录 | 病症项不计，档内用资料、年限、热度 |
| 排序失败 | 仍保证 3999 在前、999 在后；档内可暂时按年限 |

## 九、和前一版文档的差别

| | 前一版 | 本版 |
|--|--------|------|
| 3999 | 浏览可穿插；筛选后匹配分能压过会员 | 默认整段在前；仅病症明显更贴的 1 名 999 可插到第 3 位及以后 |
| 权重 | 可能改写会员顺序 | 只决定每个会员档内部的先后 |
| 病症从哪来 | 主要靠本功能筛选和行为 | 先看整站搜索、下单，再看本功能行为；本次筛选最强 |
| 产品范围 | 像单独推荐引擎 | 包月找人是小程序中的一个功能，读整站偏好 |

## 十、计算顺序

```
pool = 默认同城可展示的人
if 有筛选或帮我找:
    pool = 硬过滤(本次条件)

g3999 = pool 里 vip == 3999
g999  = pool 里其余

首页满分：下单病症28 + 搜索病症12 + 本功能病症10 + 地区10 + 资料25 + 热度15
筛选后满分：本次病症40 + 本次预算15 + 本次地区10 + 历史病症10 + 资料10 + 热度15
没有信号的项按比例摊回资料与热度
病症分差 ≥ 20 时，热度不得改写先后
接通率不进分

结果 = 按 score 降序(g3999) + 按 score 降序(g999)
若 3999 人数 ≥ 6，且某 999 的病症分 ≥ 下一位 3999 的病症分 + 20：
    只把这 1 人插到第 3 位或更后（筛选后一屏同样最多 1 人）
分页，每页 10
若用户选价格排序：先按价格，同价再按 3999 然后 999，同档再用 score，不穿插
```
