### 公共字段（与现网一致，每条事件默认携带）

> **全部为现网原有公共字段，本需求只沿用、不新增公共字段。** 含 `product_id`、`sku_id`——以前公共字段里就有，不是包月另造的。有固定取值的写在「枚举/取值」列，无则标自由值。

| 公共字段 | 含义 | 为什么需要 | 来源 | 枚举/取值 |
|---|---|---|---|---|
| `anonymous_id（open_id）` | 未登录用户唯一标识 | 未登录也能逛很久，所以非常重要 | 现网沿用 | —（自由值） |
| `user_id` | 登录用户 ID | 登录以后识别用户 | 现网沿用 | —（自由值） |
| `event_time` | 行为发生时间【时长】 | 计算时长，单位秒 | 现网沿用 | —（数值，单位秒） |
| `create_time` | 创建时间 | 记录创建时间 | 现网沿用 | —（时间） |
| `login_status` | 登录状态 | 区分登录/未登录 | 现网沿用 | `logged_in` 已登录 / `anonymous` 未登录 |
| `city_code` | 当前服务城市 | 按城市分析 | 现网沿用 | —（城市编码） |
| `source_page` | 从哪个页面进入【当前页面的前置页面】 | 判断流量来源 | 现网沿用 | `home` / `monthly_home` / `monthly_list` / `monthly_detail` / `monthly_mine` / `monthly_mine_fav` / `monthly_mine_contact` / `pay_sheet` 等 |

| `sku_id` | 商品规格 ID | 区分具体规格；非购场景可空 | 现网沿用 | —（自由值；购买链路须赋值） |

**包月场景取值约定（字段本身不新增，只约定怎么填）**

| 字段 | 包月取值约定 |
|---|---|
| `source_page` | 前置页编码，如 `home`（金刚位进包月）、`monthly_home`、`monthly_list`、`monthly_detail`、`monthly_mine` / `monthly_mine_fav` / `monthly_mine_contact`、`pay_sheet` 等；指**进入当前页之前**的页面，不是当前页自己 |
| `product_id` / `sku_id` | **沿用现网公共字段**；通话包购买/支付相关事件须赋值为后台套餐商品与规格；找人浏览类事件按现网约定可空 |
| `login_status` | 仅用 `logged_in` / `anonymous`，不用 1/0 或 true/false |

## 算法所需数据：从埋点怎么算

> 对应《包月服务-排序因子合篇》三层：无行为 / 有过行为 / 筛选项。  
> **原则：** 客户端只报行为明细；**次数、率、落层、q 值由数仓 / 特征服务计算**后供算法，不在端上算分。

### A. 数据流

```text
埋点明细（user_id / caregiver_id / option_id / 时间）
        ├─ 护理员域汇总（跨用户）→ 曝光 UV、备选人数、联系人数、采纳人数 → 热度四率
        ├─ 用户域汇总（近 90 天）→ 病症点击分布、偏好四维点击分布、是否看过详情、是否采用过某人
        └─ 当次请求上下文 → 当前是否勾选病/预算 → 落「筛选项」层
                ↓
        算法排序服务读特征，输出列表顺序
```

### B. 落层判定（三层互斥，同一时刻只落一层）

| 层 | 判定条件 | 埋点 / 数据怎么判定 |
|---|---|---|
| 筛选项 | 当次（或结果请求）勾了病症和/或预算 | 请求参数；或最近一次 `monthly_home_skill_confirm` / `monthly_home_budget_confirm` / `monthly_list_skill_confirm` / `monthly_list_price_confirm` 写入的筛选快照非「不限」 |
| 有过行为 | 未勾病·预算，但近窗有有效行为 | 存在 `monthly_filter_option_click` 或 `monthly_filter_sheet_open` 或 `monthly_detail_view` 或更多筛选相关 confirm；或历史关注/采用等产品约定的有效信号 |
| 无行为 | 未勾病·预算，且无上述有效行为 | 以上皆无 |

说明：初次 / 非初次只影响首页文案与条数，**不等于**无行为 / 有过行为。

### C. 护理员域指标（热度原料 · 跨用户）

统计窗口建议与算法一致（可配置；合篇示例含近 30 天全站均值用于收缩）。同一用户对同一护理员多次行为，**人数类指标按 UV 去重**（采纳人数、联系人数、备选人数、曝光人数均为人数而非次数，除非算法另行要求 PV）。

| 算法信号 | 汇总口径 | 来源埋点 | 计算公式（合篇） |
|---|---|---|---|
| 曝光人数（分母） | 对 `caregiver_id`，统计有过卡片曝光的去重 `user_id` | `monthly_home_recommend_expose` ∪ `monthly_list_card_expose` ∪ `monthly_expand_card_expose` | 曝光人数 = UV |
| 曝光 UV（曝光达成） | 同上 | 同上 | 曝光达成率 = min(1, log(曝光UV) / log(2000)) |
| 备选人数 | 对该护理员发生过加入备选的去重用户 | `monthly_shortlist_add`；替换成功时新人计 `monthly_shortlist_replace` 的 `new_caregiver_id` | 备选率 = 备选人数 ÷ 曝光人数 |
| 联系人数 | 对该护理员「已发起拨打」的去重用户 | `monthly_call_result` 且 result=已发起拨打（不要用仅 click 或拉起购买） | 被联系率 = 联系人数 ÷ 曝光人数 |
| 采纳人数 | 对该护理员标记采用的去重用户 | `monthly_adopt_confirm`（取消采用是否从人数中剔除：建议采用态以当前有效采用为准，与合篇「采纳」对齐） | 采纳率 = 采纳人数 ÷ 曝光人数 |
| 热度综合 | 四信号加权 | 上表 | 热度分按合篇：满分 8 拆为 4.0/2.0/1.6/0.4 再乘各率；小样本收缩 r′=(r×n+r₀×m)/(n+m)，m=30，r₀=近 30 天全站均值 |

**卡片曝光次数（PV）与详情曝光次数：**  
- 卡片曝光 PV = 上述三个 `*_expose` 事件计数（可按场景拆分）。  
- 详情曝光次数 = `monthly_detail_view` 计数（可按 `caregiver_id` 汇总 PV 或 UV）。  
算法热度分母用**曝光人数（UV）**；运营看板可同时看 PV。

### D. 用户域指标（有过行为层 · 点击分布）

窗口：**近 90 天**。点击记录按「用户 × 维度 × 选项」聚合。

| 规则 | 口径 |
|---|---|
| 去重 | 同一用户对同一 `option_id` **同一秒内连点只算 1 次** |
| 病症封顶 | 单病症累计点击次数 **封顶 10** |
| 取消 | `action=unselect` 不增加点击票数；是否回扣历史票数默认**不回扣**（只统计 select）；若产品改为回扣需单独立项 |
| 主埋点 | **`monthly_filter_option_click`**（必接）。`*_confirm` 只表示当次筛选提交，**不能**代替选项点击分布 |

#### D1 筛选项点击·病症

| 步骤 | 计算 |
|---|---|
| 1 | 从 `monthly_filter_option_click` 取 `filter_dim=skill` 且 `action=select`，按用户×`option_id` 计次（秒级去重、单病封顶 10） |
| 2 | 总点击 = 该用户所有病症选项点击次数之和 |
| 3 | 命中点击 = 护理员病症覆盖集合 ∩ 用户点过病症 的点击次数之和 |
| 4 | q_病症 = 命中点击 ÷ 总点击（总点击为 0 则本项为 0，并可能不应落在有过行为层） |

#### D2 筛选项点击·偏好（证 / 年龄 / 身高 / 性别）

| 维度 | filter_dim | 子权重（合篇） |
|---|---|---|
| 证 | `health_cert` | 0.40 |
| 年龄 | `age` | 0.25 |
| 身高 | `height` | 0.20 |
| 性别 | `gender` | 0.15 |

| 步骤 | 计算 |
|---|---|
| 1 | 各维从 `monthly_filter_option_click` 取对应 `filter_dim`+`select`，按选项计次 |
| 2 | q_维 = 护理员落在该档的点击次数 ÷ 该维总点击；未点过的维不参与，权重在剩余维按比例放大 |
| 3 | q_偏好 = 0.40×q_证 + 0.25×q_年龄 + 0.20×q_身高 + 0.15×q_性别（仅对参与维归一后） |
| 4 | 四维全未点 → 偏好项为 0，合篇：应退回无行为层判定 |

#### D3 自己采纳过（排除）

| 情形 | 数据 | 处置 |
|---|---|---|
| 本人采用过该护理员 | 用户采用状态表；可由 `monthly_adopt_confirm` / `monthly_adopt_cancel` 维护 | **排除**，不进有过行为层推荐 |
| 仅采用过相似护理员 | 证书档+病症重叠等算法侧规则 | 正常参与 |
| 无采用 | — | 正常参与 |

### E. 筛选项层（当次硬条件 + 匹配分）

| 数据 | 来源 | 用途 |
|---|---|---|
| 当前病症 / 预算 | 列表请求参数；confirm 事件快照 | 硬过滤进池；病症匹配分、预算分段（合篇病症支 / 预算档） |
| 护理员资料字段 | 供给侧（会员档、证、经验、技能、年限、报价等） | 非埋点；埋点不替代主数据 |

### F. 行为事件 → 算法用途速查

| 埋点 event_code | 算法 / 特征用途 |
|---|---|
| `monthly_home_recommend_expose` / `monthly_list_card_expose` / `monthly_expand_card_expose` | 护理员曝光 UV/PV；热度分母 |
| `monthly_detail_view` | 详情曝光；有过行为判定；样本门槛参考 |
| `monthly_filter_option_click` | **病症点击分布、偏好四维点击分布（核心）** |
| `monthly_filter_sheet_open` | 辅助「点过筛选」判定 |
| `monthly_*_skill_confirm` / `*_budget_confirm` / `*_price_confirm` / `*_more_confirm` | 当次筛选快照；筛选项层；不可替代 option_click |
| `monthly_shortlist_add` / `monthly_shortlist_replace` | 备选人数 |
| `monthly_call_result`（已发起） | 联系人数 |
| `monthly_adopt_confirm` / `monthly_adopt_cancel` | 采纳人数；自己采纳排除 |
| 其余浏览/支付等 | 产品分析与转化漏斗；非合篇热度主路径 |

### G. 验收（算法数据）

1. 任意护理员可算出：曝光 UV、备选/联系/采纳人数及四率；与埋点抽样对得上。  
2. 用户近 90 天病症点击分布仅依赖 `monthly_filter_option_click`，不依赖 confirm。  
3. 仅打开抽屉未点选项、或仅点查看结果，不应凭空产生病症点击票。  
4. `monthly_call_click` 进入购买未拨出，不得计入联系人数。  
5. 本人已采用护理员不出现在有过行为层推荐（排除规则）。

## 验收关注（建议）

1. `monthly_view_list_click` → `monthly_list_view` → `monthly_list_card_click` / `monthly_expand_card_click` → `monthly_detail_view` 可串联。
2. `monthly_call_click` 与 `monthly_call_result`、`monthly_pay_result` 可区分「点了拨打 / 真拨出 / 先买包」。
3. 空城（`monthly_empty_city_expose`）与外扩（`monthly_expand_*`）互斥场景不混报。
4. 备选满员：`monthly_shortlist_full_expose` 与 `monthly_shortlist_replace` / `replace_close` 成对。
5. 支付成功 `monthly_pay_result` 成功后**不应**自动带出 `monthly_call_result=已发起`。
6. **`monthly_filter_option_click` 必报**；与算法病症/偏好点击分布抽样一致（见上文 G）。
7. 热度四率抽样：曝光∪备选∪拨打∪采用按 `caregiver_id` 可复算。
