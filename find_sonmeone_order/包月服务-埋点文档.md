### 修订摘要（V5.30.2）

相对 V5.30.1：

- **标记采用**：`monthly_adopt_confirm`（及暂不/取消采用）补 `current_page`，区分详情 / 我的·已联系等操作页
- **客服补偿站内信**：新增系统通知点击事件；点「包月服务/赠送通话次数到账」跳转包月服务首页
- **页面/模块对齐**：同一 `business_page` 的中文「页面/模块」统一；`monthly_detail` ↔「人员详情」（不再用「详情页」/技能/证书等拆名）；页内操作只用 event_name 区分

### 修订摘要（V5.30.1）

相对 V5.30.0，按最新 PRD / 原型补齐：

- **拨打链路**：点拨打 →（无次数）首购/再买 →（有次数且会扣次）消耗确认 → 系统电话弹窗 → 点「呼叫」才扣次并发起；免扣次复拨跳过消耗确认
- **再买原因**：区分次数用完 `used` / 过期清零 `expired`
- **订单口径**：订单详情「到账次数」改为「购买次数」；客服补偿挂未过期订单，带 `order_id`，剩余可变
- **健康证筛选**：`health_cert` 仅 `unlimited` / `yes`（无未持有）
- **全平台无人**：新增冷启动空态曝光（与同城无人区分）

**包月场景取值约定（字段本身不新增，只约定怎么填）**

| 字段 | 包月取值约定 |
|---|---|
| `source_page` | 前置页编码，如 `home`（金刚位进包月）、`sys_notice`（系统通知点补偿到账进包月首页）、`monthly_home`、`monthly_list`、`monthly_detail`、`monthly_mine` / `monthly_mine_fav` / `monthly_mine_contact`、`pay_sheet` 等；指**进入当前页之前**的页面，不是当前页自己 |
| `product_id` / `sku_id` | **沿用现网公共字段**；通话包购买/支付相关事件须赋值为后台套餐商品与规格；找人浏览类事件按现网约定可空 |
| `login_status` | 仅用 `logged_in` / `anonymous`，不用 1/0 或 true/false |

## 算法所需数据：从埋点怎么算

> 对应《包月服务-排序因子合篇》三层：无行为 / 有过行为 / 筛选项。  
> **原则：** 客户端只报行为明细；**次数、率、落层、q 值由数仓 / 特征服务计算**后供算法，不在端上算分。

### A. 数据流

```text
埋点明细（caregiver_id / 时间 / 事件）
        ├─ 护理员域汇总 → 曝光次数、备选次数、拨打次数、采用次数、浏览详情次数 → 热度四率
        │     （全部按事件条数，不对用户去重）
        ├─ 用户域汇总（近 90 天）→ 病症点击分布、偏好四维点击分布、是否看过详情、是否采用过某人
        └─ 当次请求上下文 → 当前是否勾选病/预算 → 落「筛选项」层
                ↓
        算法排序服务读特征，输出列表顺序
```

### B. 落层判定（三层互斥，同一时刻只落一层）

| 层 | 判定条件 | 埋点 / 数据怎么判定 |
|---|---|---|
| 筛选项 | 当次（或结果请求）勾了病症和/或预算 | 请求参数；或最近一次 `monthly_home_skill_confirm` / `monthly_home_budget_confirm` / `monthly_list_skill_confirm` / `monthly_list_price_confirm` 写入的筛选快照非「不限」 |
| 有过行为 | 未勾病·预算，但近窗有有效行为 | 存在 `monthly_filter_option_click` 或 `monthly_filter_sheet_open` 或 `monthly_detail_view` 或更多筛选相关 confirm；或历史关注/采用等产品约定的有效信号 |
| 无行为 | 未勾病·预算，且无上述有效行为 | 以上皆无 |

说明：初次 / 非初次只影响首页文案与条数，**不等于**无行为 / 有过行为。

### C. 护理员域指标（热度原料 · **只计次数，不对用户去重**）

> **硬性口径：** 曝光 / 备选 / 拨打 / 采用 / 浏览详情 = **事件条数**。禁止 `COUNT DISTINCT user_id` / `anonymous_id`。同一用户对同一护理员做 10 次，计 10。  
> 统计窗口与算法一致（可配置；合篇示例常用近 30 天）。

#### C0. 名词定义（→ 埋点）

| 名词 | 定义 | 用哪些埋点 | 计数规则 |
|---|---|---|---|
| **曝光** | 护理员卡片进入可视区并成功上报 | `monthly_home_recommend_expose` + `monthly_list_card_expose` + `monthly_expand_card_expose` | **1 条事件 = 1 次**，不对用户去重 |
| **浏览详情** | 人员详情页加载成功 | `monthly_detail_view` | **1 条 = 1 次**，返回再进再计，不对用户去重 |
| **备选** | 成功加入备选，或替换成功使该人成为新人 | `monthly_shortlist_add`；`monthly_shortlist_replace`（计 `new_caregiver_id`） | **每次成功 = 1 次**；移出不减历史次数 |
| **拨打** | 实际发起拨号（已发起，非仅点按钮） | `monthly_call_result` 且 `result=1` | **每次已发起 = 1 次**；click / 拉起购买不计 |
| **采用** | 成功标记采用 | `monthly_adopt_confirm` | **每次 confirm = 1 次**；取消不回扣次数 |

| 易混 | 说明 |
|---|---|
| 曝光 vs 浏览详情 | 卡片曝光 ≠ 进详情；进详情只加 \(D\)，不加 \(E\) |
| 拨打 | 热度只用 `call_result=1`，不用 `call_click` |

#### C1. 基础次数（按 `caregiver_id`，窗口内）

\[
\begin{aligned}
E &= \#(\texttt{home\_recommend\_expose}) + \#(\texttt{list\_card\_expose}) + \#(\texttt{expand\_card\_expose}) \\
D &= \#(\texttt{monthly\_detail\_view}) \\
S &= \#(\texttt{shortlist\_add}) + \#(\texttt{shortlist\_replace}\land new=该人) \\
C &= \#(\texttt{call\_result}\land result=1) \\
A &= \#(\texttt{adopt\_confirm})
\end{aligned}
\]

`#` = `COUNT(*)` 事件条数，**禁止**按用户去重。

#### C2. 率（分母 = 曝光次数 \(E\)；\(E=0\) 则率 = 0）

| 率 | 公式 |
|---|---|
| 备选率 | \(r_S = S / E\) |
| 拨打率 | \(r_C = C / E\) |
| 采用率 | \(r_A = A / E\) |
| 详情率（可选） | \(r_D = D / E\) |
| 曝光达成（可选） | \(\min(1,\ \log(E+1)/\log(2000))\)（此处 \(E\) 为**次数**） |

#### C3. 热度综合（权重以算法合篇为准；示例 4.0 / 2.0 / 1.6 / 0.4）

\[
r'_x = \frac{r_x \cdot E + r_{0x}\cdot 30}{E + 30},\quad
\text{热度} = 4.0\,r'_E + 2.0\,r'_S + 1.6\,r'_C + 0.4\,r'_A
\]

### D. 用户域指标（有过行为层 · 点击分布）

窗口：**近 90 天**。点击记录按「用户 × 维度 × 选项」聚合。

| 规则 | 口径 |
|---|---|
| 去重 | 同一用户对同一 `option_id` **同一秒内连点只算 1 次** |
| 病症封顶 | 单病症累计点击次数 **封顶 10** |
| 取消 | `action=unselect` 不增加点击票数；是否回扣历史票数默认**不回扣**（只统计 select）；若产品改为回扣需单独立项 |
| 主埋点 | **`monthly_filter_option_click`**（必接）。`*_confirm` 只表示当次筛选提交，**不能**代替选项点击分布 |

#### D1 筛选项点击·病症

| 步骤 | 计算 |
|---|---|
| 1 | 从 `monthly_filter_option_click` 取 `filter_dim=skill` 且 `action=select`，按用户×`option_id` 计次（秒级去重、单病封顶 10） |
| 2 | 总点击 = 该用户所有病症选项点击次数之和 |
| 3 | 命中点击 = 护理员病症覆盖集合 ∩ 用户点过病症 的点击次数之和 |
| 4 | q_病症 = 命中点击 ÷ 总点击（总点击为 0 则本项为 0，并可能不应落在有过行为层） |

#### D2 筛选项点击·偏好（证 / 年龄 / 身高 / 性别）

| 维度 | filter_dim | 子权重（合篇） |
|---|---|---|
| 证 | `health_cert` | 0.40 |
| 年龄 | `age` | 0.25 |
| 身高 | `height` | 0.20 |
| 性别 | `gender` | 0.15 |

| 步骤 | 计算 |
|---|---|
| 1 | 各维从 `monthly_filter_option_click` 取对应 `filter_dim`+`select`，按选项计次 |
| 2 | q_维 = 护理员落在该档的点击次数 ÷ 该维总点击；未点过的维不参与，权重在剩余维按比例放大 |
| 3 | q_偏好 = 0.40×q_证 + 0.25×q_年龄 + 0.20×q_身高 + 0.15×q_性别（仅对参与维归一后） |
| 4 | 四维全未点 → 偏好项为 0，合篇：应退回无行为层判定 |

#### D3 自己采纳过（排除）

| 情形 | 数据 | 处置 |
|---|---|---|
| 本人采用过该护理员 | 用户采用状态表；可由 `monthly_adopt_confirm` / `monthly_adopt_cancel` 维护 | **排除**，不进有过行为层推荐 |
| 仅采用过相似护理员 | 证书档+病症重叠等算法侧规则 | 正常参与 |
| 无采用 | — | 正常参与 |

### E. 筛选项层（当次硬条件 + 匹配分）

| 数据 | 来源 | 用途 |
|---|---|---|
| 当前病症 / 预算 | 列表请求参数；confirm 事件快照 | 硬过滤进池；病症匹配分、预算分段（合篇病症支 / 预算档） |
| 护理员资料字段 | 供给侧（会员档、证、经验、技能、年限、报价等） | 非埋点；埋点不替代主数据 |

### F. 行为事件 → 算法用途速查

| 埋点 event_code | 算法 / 特征用途 |
|---|---|
| `monthly_home_recommend_expose` / `monthly_list_card_expose` / `monthly_expand_card_expose` | 曝光**次数** \(E\)（不去重）；热度分母 |
| `monthly_detail_view` | 浏览详情**次数** \(D\)（不去重）；有过行为判定 |
| `monthly_filter_option_click` | **病症点击分布、偏好四维点击分布（核心）** |
| `monthly_filter_sheet_open` | 辅助「点过筛选」判定 |
| `monthly_*_skill_confirm` / `*_budget_confirm` / `*_price_confirm` / `*_more_confirm` | 当次筛选快照；筛选项层；不可替代 option_click |
| `monthly_shortlist_add` / `monthly_shortlist_replace` | 备选**次数** \(S\)（不去重） |
| `monthly_call_result`（`result=1` 已发起） | 拨打**次数** \(C\)（不去重）；不含仅打开消耗确认/电话弹窗未呼叫 |
| `monthly_adopt_confirm` | 采用**次数** \(A\)（不去重）；`cancel` 仅维护状态、不回扣次数 |
| 其余浏览/支付等 | 产品分析与转化漏斗；非合篇热度主路径 |

### G. 验收（算法数据）

1. 任意护理员可按**次数（不去重）**算出：曝光 \(E\)、备选 \(S\)、拨打 \(C\)、采用 \(A\)、浏览详情 \(D\) 及 \(S/E,C/E,A/E\)；与埋点抽样对得上。  
2. 用户近 90 天病症点击分布仅依赖 `monthly_filter_option_click`，不依赖 confirm。  
3. 仅打开抽屉未点选项、或仅点查看结果，不应凭空产生病症点击票。  
4. `monthly_call_click` 进入购买/再买/消耗确认/电话弹窗但未点「呼叫」，不得计入拨打次数；仅 `monthly_call_result` 且 `result=1` 计入。  
5. 本人已采用护理员不出现在有过行为层推荐（排除规则）。  
6. 热度分母与分子均为 PV，**不对用户去重**。

## 验收关注（建议）

1. `monthly_view_list_click` → `monthly_list_view` → `monthly_list_card_click` / `monthly_expand_card_click` → `monthly_detail_view` 可串联。
2. 拨打主路径：`monthly_call_click` →（无次数）`repurchase_*`/`pay_*` 或（有次数）`monthly_consume_*` → `monthly_dial_*` → `monthly_call_result=1` → `monthly_adopt_sheet_expose`。
3. 免扣次复拨：`monthly_call_click` → `monthly_dial_expose`（无 consume）→ 点呼叫后 `call_result=1` 且 `deducted=0`。
4. 再买：`repurchase_reason` 在用完/过期两种文案场景取值正确（`used` / `expired`）。
5. 空城（`monthly_empty_city_expose`）、冷启动（`monthly_cold_start_expose`）、外扩（`monthly_expand_*`）互斥场景不混报。
6. 备选满员：`monthly_shortlist_full_expose` 与 `monthly_shortlist_replace` / `replace_close` 成对。
7. 支付成功 `monthly_pay_result` 成功后**不应**自动带出 `monthly_call_result=1`。
8. 客服补偿 `monthly_comp_credit_grant` 必带 `order_id`；订单详情剩余次数与账户剩余可对上。
9. 系统通知点补偿到账：`monthly_comp_notice_click` → 进入 `monthly_home_view`（`source_page=sys_notice`）。
10. `monthly_adopt_confirm` 必带 `current_page`（详情 vs 我的·已联系可区分）。
11. **`monthly_filter_option_click` 必报**；健康证筛选项无 `no`（未持有）。
12. 热度四率抽样：曝光∪备选∪拨打∪采用按 `caregiver_id` 以**次数**可复算（不去重）。
